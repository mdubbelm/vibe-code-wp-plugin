What is vibe coding?

You describe in plain language what you want.

The AI writes the code.

You steer, test, and iterate.

This is not learning to code. This is learning to collaborate with AI.
Term coined by Andrej Karpathy (early 2025). The trick is not understanding the code, but being able to assess the result. For people without programming experience, this is the most direct way to actually build something that works.

When it works, and when it doesn't

✓ Works well for

  • Quick prototypes
  • Internal tools, small utilities
  • Testing an idea before hiring a developer
  • Learning by reading the generated code

✗ Doesn't work for

  • Production sites with real users
  • Complex integrations
  • Anything where you can't verify the result
  • "Done without review"

Today: demo content only. No client code, no real data in the AI chat.

Being honest about the limits is part of the skill. A vibe-coded plugin is a starting point, not a finished product. Demo content only: some free AI tiers use what you send to improve their products. Check the terms of the tool you use before you paste anything real into it.

The real skill

Not:

Writing code

But:

Describing clearly what you want

Judging what you get back

This is the core message. The effort isn't in learning syntax. It's in: 1) enough detail in your prompt: what should it do, where, how does it behave 2) reading the output critically: does it work, is it safe, do I understand what it's doing Today the second half gets its own tool and its own round.

Plugin Check

Let a tool look at it

  1. Tools → Plugin Check, choose your plugin.
    Not under Tools? Plugins → Add Plugin → search "Plugin Check" → install, activate.
  2. Categories: untick Plugin Repo, tick Security only.
  3. Click Check it!
  4. Pick one Error. The technical name is in the Code column.
Plugin Repo = directory paperwork (readme.txt, License line, prefixes).
It says nothing about whether your site is safe.

What did Plugin Check find?

  • Security only: zero? 1 to 5? More?
  • Who fixed a Security finding? Who ended up fixing paperwork?

Zero findings doesn't mean safe.

Plugin Check reads code patterns. It can't see "1 minutes", or a maintenance mode that locks you out.

Reflection 2 / 4

Would you put this on a real site?

  • Who can trigger this code: visitors, editors, or only you?
  • What does it do with text someone else typed?
  • What happens when it breaks: a wrong number, a white screen, or locked out of wp-admin?
  • Who updates it next year when WordPress changes?

Reflection 3 / 4

A thought experiment

Your plugin sends new comments to an AI to summarise them.

A visitor writes a comment with instructions for that AI in it.

What stops the AI from following them?

This is called prompt injection. In 2025 Willison's assessment was that there is still no reliable way to guarantee the AI won't follow them. Keep text from strangers away from AI features that can do things.

About 1.5 min. Ask the question, wait for answers, then show the last line.
Reflection 4 / 4

When to hire a developer

  • It handles payments, personal data, logins or file uploads
  • Other people will use it, or it runs on a client's site
  • It stores things in the database or has a form
  • Plugin Check still shows errors after two rounds of "fix this", and you can't tell whether they're real
  • You can't explain in one sentence what each part does

A vibe-coded plugin is a very good brief for a developer. Bring it, together with your prompt.
